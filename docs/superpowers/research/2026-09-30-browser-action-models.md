## 2. Encoder-only rankers for element selection

- **Accuracy.** A pointwise DeBERTa-base cross-encoder is a good *filter* (R@50 88.9) and a bad *chooser* (R@1 25.4; top-1 ele 26.8 / 21.6 / 24.5) [M]. Best published encoder top-1 is Dual-VCR's 38.4 R@1 [M]. Laya's 421M option-scorer at 50.3 / 48.2 / 48.4 ele [M] is the closest analogue to Von: one pass, text-only, ≈20 lexically-shortlisted candidates, within 5 pt of the 3B two-stage MindAct cross-task and *above* it cross-website/domain.
- **Inputs that helped.** MindAct: tag + text + salient attributes + parent and child text; query = task + previous actions [M]. Dual-VCR: nearest neighbours' HTML text ordered by bbox-centre distance gave +11.9 R@1; pixel ROI features added only +1.1 R@1 and +1.4 reader ele [M]. Prune4Web: structural pruning to ~20 keeps 97.5 % recall [M].
- **Losses.** MindAct: BCE with random same-page negatives [M]. WEPO: DOM-distance (LCA) negatives at 1:3 beat random at 1:5 by 1.1 pt SR; elbow at 3 negatives [M]. [Controlled cross-encoder study](https://arxiv.org/html/2603.03010v2): listwise InfoNCE and pairwise MarginMSE consistently beat pointwise BCE, "switching objective yields gains comparable to moving up one backbone size tier", MiniLM-33M matched ELECTRA-110M, and with matched hard-negative pools a plain hinge loss equalled LLM listwise distillation (0.56 vs 0.53 nDCG OOD) [M, IR domain].
- **Latency.** MindAct, Dual-VCR, WEPO and Prune4Web report none [M: absent]. Encoder numbers that exist: Laya ≈33 ms/pass (GPU, 512 ctx), Von 23 ms A10G vs 360 ms CPU [M]. Our 400→817 ms at 47 options says cost is total sequence length: option count × tokens per option [M/I].

## 3. Techniques that transfer to a text-only, single-pass, fixed-harness scorer

- **Representation.** Neighbour and ancestor/label text is the largest measured gain for an encoder ranker [M]. Form membership and section heading are the text form of "nearest neighbours" [I]. Tagging options by viewport position is free once bboxes exist [M→I]. jev-ultrafast carries ≤6 000 chars of visible page text; our state is controls-only, so DONE/BLOCKED decide blind [M].
- **Training.** Listwise softmax over the option set with same-page decoys as negatives (InfoNCE concentrates gradient on confusable elements); weight negatives by DOM/geometry distance (WEPO) [M]. Soft teacher targets: MarginMSE distillation is top-tier in the controlled study, Laya trains with soft CE + a proper scoring rule, [GUI-SD](https://arxiv.org/abs/2605.00642) reports entropy-weighted teacher distillation beating GRPO [M]. Instruction diversity: [UI-Ins](https://arxiv.org/abs/2510.20286) found 23.3 % of grounding instructions flawed and gains from appearance/function/spatial/intent paraphrases [M, VLM]. Label smoothing and curriculum: no GUI evidence found [I].
- **Inference.** Cascades: MindAct top-50, Laya ≈20, Prune4Web R@20 97.5 % [M]; a cheap pre-filter keeping 20–30 candidates plus all moves loses little. Operation + target in one request (jev) is what our act head already does [M]. Cross-step caching of option encodings is impossible in Von's option-marker design (options attend to a prefix that changes each step); it needs a bi-encoder or late-interaction head, unexplored for GUIs [I]. Escalating to the chat LLM only on a small top-2 margin mirrors Avenir-Web's fallback layering and SeeAct's 20–25 pt grounding gap [M→I].

## 4. Ceiling for a text-only ~400M scorer

Offline Mind2Web conflates *planning* (which step next, from a task-level goal) with *grounding*. With planning oracle, DOM-text grounding reaches 90.4 % (703/777) and vision adds nothing over DOM ([From Grounding to Planning](https://arxiv.org/html/2409.01927v1)) [M]; with grounding oracle, planning stays at 47–49 % [M]. Text-only encoders given only the task goal plateau near 50 % ele cross-website (Laya 48.2, MindAct-XL 42.0, Dual-VCR ~47 CT) [M]; 7B screenshot VLMs with planning inside reach 68–76 [M]. Our Act receives a step-scoped goal from the chat model, so the relevant ceiling is the grounding one, ≈85–90 % on real pages; our 0.926 on fixtures is consistent [I]. Cheap visual features: geometry (neighbour ordering, position) delivers most of Dual-VCR's gain, pixels ≈1 pt; not worth an image tower on WebGPU [M→I].

## Ranked changes

1. **Context-enriched option lines** (accessible name + nearest label/heading + form or landmark + up to 2 neighbours' text, ordered by bbox distance). Evidence: +11.9 R@1 / +4.6 ele (Dual-VCR), parent/child text (MindAct) [M]. Expect +3–6 pt on ambiguous pages [I]; ~1.5–2× tokens per option unless paired with #2. Cost: medium (`observation.ts` + re-render rows).
2. **Geometry/lexical pre-filter to ≤24 options before Von.** Evidence: Laya ≈20, Prune4Web R@20 97.5 %, our 400→817 ms scaling [M]. Expect p50 ≈250 ms, worst ≈350 ms, <3 pt recall loss if it keeps goal-token, role and viewport matches plus all moves [I]. Cost: low (pure TS + tests).
3. **Listwise loss with distance-weighted same-page negatives.** Evidence: objective ≈ one size tier; distance negatives +1.1 pt (WEPO) [M]. Expect +2–4 pt [I]. Cost: low in `train.py`; needs bbox/DOM path in rows.
4. **Soft-label distillation from teacher logprobs** (26B chat model, or Claude for Mind2Web rows). Evidence: MarginMSE top tier; Laya soft CE; GUI-SD [M]. Expect +1–2 pt and lower ECE (already 0.145→0.054 from fine-tuning) [I]. Cost: re-label with logprobs.
5. **Goal paraphrase augmentation** (appearance / function / spatial / intent). Evidence: UI-Ins [M, VLM]. Expect +1–3 pt cross-website [I]. Cost: low, one teacher batch.
6. **Bounded page-text excerpt in the state** (≤1 500 chars around the viewport). Evidence: jev's ≤6 000 chars; planning is the bottleneck [M]. Expect fewer premature DONE, better BLOCKED; +20–40 % tokens, so pair with #2 [I]. Cost: low.
7. **Runtime diet:** shorter option rendering, int8/fp16 weights, fixed-shape batching so ORT WebGPU reuses compiled kernels. Evidence: Laya 33 ms and Von 23 ms on GPU show the model is not the floor; ShowUI 1.4× from token pruning [M]. Expect 20–40 % latency [I]. Cost: medium (export + golden re-verify).
8. **Margin-gated escalation to the chat LLM** (top-2 probability gap < τ). Evidence: SeeAct grounding gap, Avenir-Web fallback [M→I]. Expect e2e accuracy up with a small latency tail. Cost: low, in `actLoop.ts`.
